# AI 校园活动策划团队 · 多 Agent 实践

华为 ICT 大赛云赛道 **赛题13（AI 校园活动策划团队多Agent实践）** 的参评作品。

四个策划角色组成一个团队，按 **创意先行 → 预算/物料/宣传三线并行** 的分阶段编排，把一个活动简报（主题、人群、规模）变成可执行的策划方案。零依赖，可直接跑。

## 团队分工

| 角色 | 职责 | 产出 |
|:--|:--|:--|
| **创意** | 定主题、定形式、排流程 | 5 段议程 + 总时长 |
| **预算** | 按规模测算各项开销 | 五类明细 + 总额 + 人均 |
| **物料** | 列清单与数量 | 6 类物料及备量 |
| **宣传** | 定渠道、排节奏 | 4 渠道 + 4 个时间节点 |

## 编排为什么分两阶段

```
阶段1：创意  ──→  确定 scale（人数）与主题
                     │
阶段2：预算 / 物料 / 宣传   ← 三者都依赖 scale
```

- **创意必须先行**：预算按人均算、物料按人数备、宣传文案要带主题，三个下游都依赖它
- **后三者互相独立**：可以并行（代码里是顺序调用，改 `asyncio.gather` 即可并发）
- 没有让"预算"去改"创意"的规模——**下游不反向修改上游决策**，避免责任混乱

## 运行

```bash
python3 main.py
python3 main.py "AI 创意市集"
python3 main.py "毕业季音乐会" --json
```

## 结构化产出

每个角色返回 `Result(role, summary, data)`，`data` 是结构化载荷，下游按需取用：

```python
@dataclass
class Result:
    role: str        # 角色名
    summary: str     # 一句话结论（给人看）
    data: dict       # 结构化载荷（给下游/给程序）
```

**摘要给人看、data 给机器用**——这两层分开，Agent 之间才不会靠解析自然语言传递信息。

## 预算模型的取舍

```
场地 800（固定）
物料 = 人数 × 6
奖品 1500（固定）
宣传 600（固定）
机动 = 上述合计 × 10%
```

刻意保持**可解释**：每个数字都能说清怎么来的。接真实报价系统时，只需把 `BudgetRole.work` 换成查价，接口不变。

## 扩展点

- 接真实 LLM：把每个 `Role.work` 里的规则替换成提示词调用，`duty` 字段就是角色提示词
- 加"风控"角色：检查预算是否超 cap、场地是否冲突
- 三线并行：`asyncio.gather(budget, material, promo)`
- 输出成 PDF/PPT：把 `results` 喂给 python-pptx 直接出策划书
