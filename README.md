# 多 Agent 面试协同团队

华为 ICT 大赛云赛道 **赛题15（多 Agent 面试协同团队实践）** 的参评作品。

**面试官 / 候选人 / 评估官** 三个 Agent 组成协同闭环，按能力项多轮问答并实时打分，最后给出加权总分与录用建议。零依赖，可直接跑。

## 三方分工

| Agent | 职责 | 关键行为 |
|:--|:--|:--|
| **面试官** | 按能力项出题 | 发现某能力项被评估官判"偏弱"，下一轮对该项**追问细节** |
| **候选人** | 作答并自带自评置信度 | 规则化应答，可替换为真实 LLM |
| **评估官** | 逐轮打分 + 汇总 | 输出加权总分、各能力条、录用建议 |

## 能力模型（可配置）

```python
DEFAULT_COMPETENCIES = [
    Competency("编程基础", 0.25),
    Competency("系统设计", 0.25),
    Competency("问题排查", 0.20),
    Competency("沟通表达", 0.15),
    Competency("学习潜力", 0.15),
]
```

权重合计 1.0，换岗位只改这张表，三个 Agent 都不用动。

## 协同闭环

```
第 n 轮：
  面试官 出题（带 competency 标签）
     ↓
  候选人 作答（带 confidence）
     ↓
  评估官 打分（写入 scores[competency]）
     ↓
  成绩反馈进 history → 影响面试官第 n+1 轮的追问策略
```

**闭环点**在于：评估官的结论会回流到面试官的下一轮提问——这才是"协同"，而不是三方各跑各的。

## 分档规则

| 加权总分 | 建议 |
|--:|:--|
| ≥ 80 | 建议录用（senior） |
| ≥ 65 | 建议录用（junior/中级） |
| ≥ 50 | 建议加面一轮 |
| < 50 | 不建议录用 |

阈值集中在 `EvaluatorAgent(threshold=0.7)`，调严调松只改一个参数。

## 设计取舍

1. **打分与决策分离**：评估官只给分，录用建议由 `report()` 按权重与阈值算，避免"边聊边定结论"
2. **候选人可插拔**：`CandidateAgent(answers=...)` 传入不同的作答集，就能模拟强/弱候选人，便于回归测试
3. **降分有依据**：只有答案明显敷衍（过短或自认经验少）才压分，不做主观臆断
4. **transcript 全量留痕**：每轮 `Turn` 都进返回值的 `transcript`，可审计

## 扩展点

- 接真实 LLM：把 `InterviewerAgent.ask` / `CandidateAgent.answer` 换成提示词调用，能力项就是评分维度
- 多面试官：并行三个 `InterviewerAgent` 分别问技术/项目/文化，评估官聚合
- 加 `ScribeAgent` 生成面试纪要（可直接复用赛题14 的邮件技能发出）
